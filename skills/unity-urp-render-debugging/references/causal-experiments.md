# Causal experiments without overclaiming

Use a counterfactual to choose the next intervention, not to turn a diagnostic into product acceptance. The observations here come from a reconstructed, unaccepted reference scene. Its controls can support within-run comparisons; they cannot prove preservation of the missing historical serialized baseline.

## A visibility exemption must survive the route

One basin was disabled when the scene was bound in the courtyard, then enabled in the approach zone. The terrain's live guard correctly hid the replacement because an exempt target was now drawing. The sky and horizon were still hidden; diagnosing every guard failure as the previously known sky problem would have missed the actual target category.

Inventory matched targets by category at bind and at each failing route state. Check site zone, independently computed zone, viewer domain and each exemption separately. Bind-time inactivity is not permanent non-visibility. Include potentially co-visible targets in the actual geometry/water proof, or enforce a specifically accepted live exclusion; do not just remove the guard.

The corrected source case increased relevant water coverage from 28 to 29 targets, with no inactive exemptions left, and baked against that stronger binding. Geometry and texture bytes stayed unchanged while the provenance changed. The subsequent import and two-view run showed the terrain in both views. This fixed visibility in that tested route; 49/70 foreground pixels still failed and the two-pixel OFF failure remained.

## Instrumentation changes the sequence it observes

A diagnostic with extra same-frame renders did not reproduce an earlier large OFF image difference. That does not disprove the earlier failure: the diagnostic changed render order. It narrowed where the change appeared in its own sequence and retained the old failure.

A supposed post-teardown persistence control also contained an active return-comfort vignette. Equal camera pose did not mean equal image state. Record comfort/fade, temporal/animation, pipeline and rendering state alongside pose. If a control is invalid, label it invalid for that inference; do not silently replace a failed acceptance image or warm up until it disappears.

## Verify clone fidelity after every adjustment

An initial clone report claimed 15/16 renderer-flag matches while separately reporting equal bounds after an override. The flag comparison had run before that override. A follow-up compared the final fields directly, including world bounds, and found all 16 pairs matched on the measured fields.

Match mesh/material references, world matrix, final bounds, layers, sorting/render priority, light/reflection-probe settings, shadows, motion vectors, property blocks and other state relevant to the experiment. Record mismatch reasons, not just one aggregate count. Equal measured fields are not a universal GPU-equivalence certificate. Backend batching and other draw context can still differ.

## Retaining the original changes occlusion

Base-only, sectors-only and combined clones were rendered while the original stayed present. Base-only caused zero changes outside the frozen allowed region; sectors caused some of the same residuals as the real replacement. That implicates an added-sector/draw-interaction path, but the original changes depth and occlusion. The residual difference between clone and replacement counts is not a direct measure of another component's causal contribution.

Compare residual sets and RGB values as well as totals. In one north view, all 29 sector-clone residuals were among the real replacement's 70 and had the same RGB; 41 were real-only. This strengthens a bounded association but does not identify a unique GPU writer or mechanism.

Changing the clone queue from the experimental 2500 to the source's 2000 worsened sector residuals in that run: 4→11 at spawn (13 on repeat) and 29→66 in the north view. This rejects that candidate queue change under the tested conditions. It is not a universal recommendation for 2500.

## Keep reference provenance visible

A reconstructed scene that passes import and functional checks is still a different reference if historical byte identity is missing. Preserve the old ledger and label the new reference explicitly. Report newly visible geometry, unchanged water checks and current failures separately. Do not present old-versus-new totals from different references as a continuous improvement curve.
